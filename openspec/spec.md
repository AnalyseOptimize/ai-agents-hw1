# Tracker

## ADDED Requirements

### Requirement: Автономная поставка

Приложение MUST работать в обычном браузере без CDN, внешних библиотек,
внешних ресурсов и API-ключей.

Вариант A MUST состоять из tracker-v2.html со встроенными CSS и JavaScript.
Вариант B MUST содержать index.html, styles.css, app.mjs, domain.mjs
и tests/acceptance.test.mjs.

#### Scenario: Автономная работа

- WHEN приложение открыто поддерживаемым для выбранного варианта способом
  без доступа к интернету
- THEN управление задачами, фильтрация и расчёты работают без внешних запросов.

### Requirement: Данные и стартовый пример

Каждая задача MUST содержать уникальный id, title, hours и done.
Без включённого сохранения приложение MUST начинать работу с тремя задачами:
«Чтение» — 2 ч, done=true; «Практика» — 4 ч, done=false;
«Повторение» — 2 ч, done=false.

#### Scenario: Первое открытие

- WHEN приложение запускается со стартовым примером
- THEN отображаются три задачи, всего 8 ч, выполнено 2 ч, прогресс 25%.

### Requirement: Изменение задач

Добавление, удаление и переключение done MUST менять данные задач,
после чего список и сводка MUST отражать актуальное состояние.
Новая задача MUST создаваться с done=false.

#### Scenario: Добавление задачи

- WHEN пользователь добавляет задачу с допустимыми названием и часами
- THEN в данных появляется новая активная задача с уникальным id,
  а список с учётом фильтра и сводка обновляются.

#### Scenario: Удаление задачи

- WHEN пользователь удаляет задачу
- THEN именно эта задача удаляется из данных, а список и сводка обновляются.

#### Scenario: Выполнение практики

- WHEN в стартовом примере пользователь отмечает «Практику» готовой
- THEN её done становится true, выполнено 6 из 8 ч, прогресс 75%.

#### Scenario: Возврат задачи в активные

- WHEN после выполнения «Практики» пользователь снимает её отметку
- THEN её done становится false, выполнено 2 из 8 ч, прогресс 25%.

### Requirement: Валидация формы

Название после trim MUST быть непустым.
Часы MUST быть конечным числом от 0,5 до 24 включительно с шагом 0,5.
Пустое значение часов MUST обрабатываться как отсутствие ввода, а не ноль.

При ошибке приложение MUST не добавлять задачу, показывать ошибку рядом
с соответствующим полем и сохранять введённые значения формы.

#### Scenario: Пустое название

- WHEN пользователь отправляет форму с пустым названием
  или названием только из пробелов
- THEN задача не добавляется, рядом с названием видна ошибка,
  значения формы сохраняются.

#### Scenario: Некорректные часы

- WHEN пользователь отправляет форму с пустыми, нечисловыми,
  отрицательными часами, нулём, значением вне диапазона
  или значением не кратным 0,5
- THEN задача не добавляется, рядом с часами видна ошибка,
  значения формы сохраняются.

#### Scenario: Допустимые границы

- WHEN пользователь вводит непустое название и часы 0,5 либо 24
- THEN форма принимает значения и добавляет задачу.

### Requirement: Общая сводка

Приложение MUST считать общие часы и выполненные часы по всем задачам.
Прогресс MUST равняться округлению до ближайшего целого значения
100 × выполненные часы / общие часы.
При отсутствии задач прогресс MUST быть 0%, без NaN и Infinity.

#### Scenario: Все задачи удалены

- WHEN пользователь удаляет все задачи
- THEN общие часы равны 0 ч, выполненные часы равны 0 ч,
  прогресс равен 0%.

#### Scenario: Округление прогресса

- WHEN в данных две задачи по 0,5 ч и 1 ч, причём выполнена только первая
- THEN общие часы равны 1,5 ч, выполненные часы равны 0,5 ч,
  прогресс равен 33%.

### Requirement: Фильтрация

Приложение MUST предоставлять фильтры «все», «активные» и «готовые».
Фильтр MUST менять только видимый список, не изменяя данные и сводку.

#### Scenario: Активные задачи

- WHEN в стартовом примере включён фильтр «активные»
- THEN видны «Практика» и «Повторение», общие часы остаются 8 ч,
  выполненные — 2 ч, прогресс — 25%.

#### Scenario: Готовые задачи

- WHEN в стартовом примере включён фильтр «готовые»
- THEN видно только «Чтение», а сводка остаётся 2 из 8 ч и 25%.

#### Scenario: Все задачи

- WHEN пользователь включает фильтр «все»
- THEN видны все существующие задачи независимо от done.

### Requirement: Читаемый интерфейс

Интерфейс MUST оставаться читаемым при ширине 390 px
без горизонтального скролла.
Поля и кнопки MUST иметь понятные подписи.

#### Scenario: Узкий экран

- WHEN приложение отображается при ширине области просмотра 390 px
- THEN поля, кнопки, список, ошибки и сводка доступны и читаемы,
  горизонтальный скролл отсутствует.

### Requirement: Необязательное сохранение

Это требование применяется только при включении улучшения localStorage.

Приложение MUST сохранять изменения задач и восстанавливать сохранённые
задачи, включая пустой список, когда хранилище доступно.
При недоступности хранилища приложение MUST показывать понятное сообщение
и продолжать работу в памяти.

Ограничение localStorage при file:// MUST быть описано:
поведение зависит от браузера, сохранение между запусками не гарантируется.

#### Scenario: Восстановление задач

- WHEN сохранение включено, хранилище доступно и приложение открывается повторно
- THEN восстанавливается сохранённый набор задач, включая пустой набор.

#### Scenario: Хранилище недоступно

- WHEN обращение к localStorage завершается ошибкой
- THEN пользователь видит сообщение о недоступности сохранения,
  а добавление, удаление, переключение done и расчёты продолжают работать в памяти.
